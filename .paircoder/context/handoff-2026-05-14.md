**Editorial implication for the public-facing site:** the OCR text +
embeddings + finds entries currently live are all keyed against the
PRE-redaction bytes. Citations like "62-HQ-83894 Section 1, page 70"
(the Wyly teletype the new finds entry cites) **point at the OLD
content** because the worker serves OCR'd text from `pages.json` which
was built from the May-12 PDF. The current-pointer R2 key now serves
the NEW (smaller) PDF, so a reader who clicks "Open PDF" gets the
redacted version while the OCR transcript on the page shows the
unredacted version.

This isn't a bug — it's the integrity guarantee working as designed.
Both versions exist at known content-addressed paths. But it's an
**editorial decision** the operator should make: do we re-OCR against
the new (redacted) bytes and flag the diff? Surface a "re-redacted
upstream" pill on affected cards? Show before/after in a new UI
surface?
